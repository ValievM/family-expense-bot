# Правила разработки

Проект: Telegram-бот и веб-панель учёта семейных расходов (Go, PostgreSQL, React, один `docker compose`).
Требования и архитектура описаны в [docs/TZ.md](docs/TZ.md), контракт API в [docs/openapi.yaml](docs/openapi.yaml).

## Проверки перед коммитом

```bash
make lint test            # gofmt, go vet, golangci-lint, юнит-тесты
make test-integration     # репозитории на настоящем PostgreSQL (нужен Docker)
cd web && npm run lint && npm run typecheck && npm test
```

Работаем прямо в `main`, без feature-веток. Один коммит равен одной логической вещи.

## Коммиты

Conventional Commits, английский, повелительное наклонение, строка до 72 символов: `feat(domain): add Expense entity and validation`.

Типы: `feat`, `fix`, `test`, `refactor`, `docs`, `chore`, `build`, `ci`. Область (scope): пакет или слой (`domain`, `expense`, `agent`, `postgres`, `httpapi`, `telegram`, `llm`, `web`, `docker`, `config`).
Нельзя: `wip`, `update`, `fix stuff`, смешивать рефакторинг и новую функцию в одном коммите, коммитить красные тесты, секреты и бинарники. В теле коммита пишем «почему», если это не очевидно.

## Код

- Архитектура: порты и адаптеры. Все интерфейсы между слоями лежат в `internal/ports`; сервисы и адаптеры зависят только от `ports` и `domain`, а не друг от друга; зависимости собирает `cmd/server`.
- Принципы: SOLID, DRY, KISS, YAGNI. Без DI-фреймворков, CQRS, event bus и абстракций «на вырост».
- Зависимости: стандартный `net/http` (`ServeMux`), `pgx`, `goose`, `log/slog`. Любую другую сначала обосновать.
- Ошибки: `fmt.Errorf("...: %w", err)`, доменные ошибки через `errors.Is/As`, без `panic` в обычном потоке.
- Деньги: целые копейки (`domain.Money`), никакого `float`; сумма из текста разбирается через `ParseRubles`.
- Доменные объекты проверяют себя в конструкторах (`NewMoney`, `NewDay`, `NewUserID`, `NewComment`, `NewExpense`); поля агрегата закрыты.
- Тесты: table-driven, понятные имена, fake вместо моков, модель в тестах только fake.
- Имена идентификаторов, код, коммиты на английском; комментарии на русском.
- Для интерфейсов компиляторная проверка `var _ Iface = ...` пишется в конце файла.

## Комментарии

Комментарии несут информацию и не шумят.

- **У интерфейсов комментариев нет** (ни у типа, ни у методов): имена говорят сами, поведение описано у реализаций.
- **Функции и методы с реальным поведением**: ровно три строки, без вводной и пустых строк:
  ```go
  // Принимает: <параметры и их смысл; «ничего», если их нет>.
  // Делает: <что делает, включая побочные эффекты и правила>.
  // Возвращает: <что и когда возвращает, включая ошибки>.
  ```
- **Без комментария**: тривиальные геттеры, обёртки `Error()`/`String()`, однострочные делегаты, тестовые фейки, стабы и хелперы, оболочка `main`, `var _ Iface = ...`. У `Test…` одна строка `// Проверяет: ...`.
- Строки до ~100 символов, без пересказа сигнатуры. Внутри функций только «почему», не «что».
- Типы, константы, переменные: одна строка и только если назначение неочевидно. Пакет: `// Package name — описание`.

## Безопасность

- `user_id` для инструментов агента **никогда не берётся из ответа модели**, только из Telegram-сообщения; на это есть тест.
- Репозиторий публичный: никаких ключей, токенов, `.env`, дампов. Только `.env.example` с пустыми значениями; `.env` и `data/` в `.gitignore`.
